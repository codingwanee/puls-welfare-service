1. API 요약

Method경로설명
GET/api/wsbd/v1/regions전체 시도·시군구 목록 조회
GET/api/wsbd/v1/welfare-policies게시 정책 목록 cursor 조회
GET/api/wsbd/v1/welfare-policies/{id}게시 정책 상세 조회

공통 요청 헤더

모든 wsbd API는 요청 추적을 위한 X-TRACE-ID 헤더를 선택값으로 받는다. Swagger UI에서도 각 API의 Header 파라미터로 입력할 수 있다.

헤더타입필수기본값설명
X-TRACE-IDstringN빈 값App·Backend·wsbd 호출 로그를 연결하는 요청 추적 ID

3. 정책 목록 조회

요청

GET /api/wsbd/v1/welfare-policies?sido={시도명}&sigungu={시군구명}&cursor={cursor}&limit={건수}
파라미터타입필수기본값설명
sidostringN서울특별시시도명
sigungustringN없음시군구명. 생략하면 해당 시도 전체 조회
cursorstringN없음이전 응답의 nextCursor. 첫 페이지는 생략
limitintegerN20페이지당 건수, 1~100

지역 조회 범위

sido=서울특별시이고 sigungu를 생략하면 다음 정책이 포함된다.

  • 전국 공통 정책: 시도·시군구가 모두 없는 정책
  • 서울특별시 공통 정책: 시도는 서울특별시이고 시군구가 없는 정책
  • 서울특별시 산하 모든 시군구 정책

sido=서울특별시&sigungu=마포구이면 다음 정책만 포함된다.

  • 전국 공통 정책
  • 서울특별시 공통 정책
  • 서울특별시 마포구 정책

시도와 시군구 조합은 /regions에 존재해야 한다. 공백 문자열은 미입력으로 처리한다.

첫 페이지 요청 예시

curl --get '{WSBD_ORIGIN}/api/wsbd/v1/welfare-policies' \
  --data-urlencode 'sido=서울특별시' \
  --data-urlencode 'limit=20' \
  -H 'Accept: application/json' \
  -H 'X-TRACE-ID: 9f53cd97-5e79-47da-8f65-5d95a4733dc8'

성공 응답 200 OK

목록 항목 필드

필드타입Null 가능설명
idinteger(int64)N정책 ID. 상세 API의 path 값으로 사용
serviceNamestringN서비스명
servicePurposeSummarystringY서비스 목적 요약
competentAgencystringY소관기관명

Cursor 처리 규칙

  • 첫 페이지 요청에는 cursor를 보내지 않는다.
  • hasNext=true이면 응답의 nextCursor를 다음 요청의 cursor로 그대로 전달한다.
  • hasNext=false이면 마지막 페이지이며 nextCursor는 null이다.
  • Cursor를 App이나 Backend에서 생성, 수정, 복호화하거나 정책 ID로 대체하지 않는다.
  • 다음 페이지에서도 최초 요청과 동일한 sido, sigungu, limit을 유지한다.
  • Cursor에는 최초 조회시각과 정렬 기준이 포함되어 있어, 페이지 조회 도중 신규 정책이 게시돼도 기존 조회 흐름에 끼어들지 않는다.
  • 화면을 새로고침할 때는 cursor 없이 첫 페이지부터 다시 조회한다.

다음 페이지 요청 예시

curl --get '{WSBD_ORIGIN}/api/wsbd/v1/welfare-policies' \
  --data-urlencode 'sido=서울특별시' \
  --data-urlencode 'limit=20' \
  --data-urlencode 'cursor=WyJ2MSIsMTc4NTgwMTYwMCwwLDAsMjA3NTcsMSwxNzg1NzE1MjAwLDAsOTRd' \
  -H 'Accept: application/json'

샘플 cursor는 문서 형식 설명용이다. 실제 연동에서는 반드시 직전 응답의 nextCursor를 사용한다.

5. 오류 응답

wsbd 오류는 admin-backend의 공통 오류 응답과 동일한 형식으로 응답한다.

{
  "timestamp": "2026-08-04T10:30:00+09:00",
  "status": 400,
  "code": "INVALID_REGION",
  "message": "유효하지 않은 지역입니다.",
  "detail": null,
  "path": "/api/wsbd/v1/welfare-policies",
  "errors": []
}
HTTP 상태code발생 조건Backend 권장 처리
400INVALID_REGION/regions에 없는 시도 또는 시군구 조합App에 입력 오류 전달 또는 지역 목록 갱신
400INVALID_CURSORcursor 형식/정렬 버전 오류 또는 limit 범위 오류저장한 cursor 폐기 후 첫 페이지 재조회
404POLICY_NOT_FOUND해당 정책 ID가 DB에 없음정책 없음 화면 처리
410POLICY_NOT_AVAILABLE정책은 존재하지만 미게시·노출 전·노출 종료 상태더 이상 이용할 수 없는 정책 화면 처리

오류 예시: 잘못된 지역

GET /api/wsbd/v1/welfare-policies?sido=서울특별시&sigungu=없는구
{
  "timestamp": "2026-08-04T10:30:00+09:00",
  "status": 400,
  "code": "INVALID_REGION",
  "message": "유효하지 않은 지역입니다.",
  "detail": null,
  "path": "/api/wsbd/v1/welfare-policies",
  "errors": []
}
